# 2026 SCC 项目申报书

## 项目名称：MoonRV Lab：基于 MoonBit 的 RISC-V 二进制分析与可视化仿真平台

---

## 项目简介

本项目拟开发一个用 MoonBit 编写的 **RISC-V 二进制分析与可视化仿真平台**。项目聚焦 `RISC-V ELF / RAW Binary / Assembly` 三类输入，把原本抽象的指令执行、控制流变化、寄存器更新和内存读写过程，通过直观的 Web UI 呈现出来，降低理解 RISC-V 程序行为的门槛。

平台既是分析工具，也是教学工作台：教师可以用它演示函数调用、分支跳转、栈帧变化和执行轨迹；可以在浏览器中单步执行程序、观察寄存器与内存变化、对照反汇编与控制流图理解程序结构；开发者也可以将其用于编译器后端验证和二进制调试。项目将统一 CLI 内核与 Web 端交互体验，在体现 MoonBit 系统软件能力的同时，更强调教学友好性、展示效果和 UI 完整度。

---

## （1）项目目标与应用场景

### 1.1 项目目标

本项目的总体目标是构建一个以 RISC-V 为核心对象、以 **教学可视化** 和 **交互式 UI 体验** 为突出特色、兼顾静态分析与动态仿真的工程化平台，重点目标包括：

1. **构建面向教学的 Web 工作台**：提供函数导航、反汇编视图、CFG 图视图、寄存器面板、内存面板和执行轨迹区，形成适合课堂讲解与实验操作的界面体系。
2. **让程序执行过程可视化、可交互**：支持单步执行、断点暂停、继续运行、状态对比和轨迹回放，能够直观看到控制流跳转、寄存器变化和内存读写过程。
3. **建立统一的 RISC-V 程序表示模型**：对 ELF、节区、符号、函数、基本块、指令、操作数、执行状态和分析结论进行统一抽象，为 UI 联动和分析展示提供稳定数据基础。
4. **设计高质量类型体系并支撑分析执行一体化**：利用 MoonBit 的代数数据类型、模式匹配和模块系统，对架构位宽、指令格式、控制流边、寄存器状态、内存区域和轨迹事件建立严格类型约束，并在同一平台上支持静态分析与动态仿真。
5. **形成适合教学和实际使用的完整交付**：提供 CLI、Web 工作台、结构化报告、标准样例和演示脚本，使项目既便于课程使用，也便于开发者将其用于编译器后端验证和二进制调试

### 1.2 应用场景

1. **RISC-V 教学实验平台**：用于演示函数调用、分支跳转、栈帧变化、寄存器更新和内存读写过程。
2. **编译器后端验证工具**：用于检查编译器生成的 RISC-V 汇编或二进制是否满足预期，并辅助定位生成错误。
3. **二进制理解与调试演示工具**：帮助开发者快速查看 ELF 信息、函数边界、控制流结构与关键执行路径。
4. **回归分析与差异对比工具**：对两个版本的程序进行反汇编、CFG 或执行轨迹差异比较，辅助定位行为变化。
5. **RISC-V 生态基础设施**：为后续更复杂的调试器、验证器、教学平台或 AI 辅助分析工具提供可复用内核。

### 1.3 解决的问题

本项目聚焦解决以下问题：

1. **RISC-V 教学过程“看不见、讲不透”**  
现有课堂中常用 `objdump + 文本终端` 方式演示，难以直观看到控制流跳转、寄存器变化和内存写入过程，教学解释成本高、学习门槛高。

2. **分析能力与执行能力割裂，工具链来回切换**  
很多工具只能“看反汇编”或只能“跑程序”，难以在同一界面完成 `反汇编 -> CFG -> 单步执行 -> 状态解释` 的闭环，影响调试效率与实验体验。

3. **对 RV64 用户态程序和 syscall/filesystem 场景支持不足**  
已有轻量方案往往停留在基础指令或静态展示，对 `RV64I/RV64IMC`、Linux 用户态 syscall 以及最小文件 I/O 场景覆盖不完整，难以支撑真实样例程序演示。

## （2）交付物说明

### 2.1 核心功能与功能边界（Scope）

**核心交付模块：**

| 模块 | 功能描述 | 优先级 |
|------|----------|--------|
| 二进制输入层 | 解析 `RISC-V ELF / RAW Binary`，读取节区、符号、入口地址和函数信息 | 高 |
| 指令模型与反汇编层 | 对 RISC-V 指令进行解码、格式化和结构化表示 | 高 |
| 静态分析层 | 构建 CFG、调用图、基础 def-use 关系和函数级摘要 | 高 |
| 执行引擎 | 支持程序装载、单步执行、断点、运行控制、寄存器/内存状态更新 | 高 |
| 系统调用与文件访问适配层 | 支持 Linux 用户态常用 syscall，并提供最小文件 I/O 能力（open/read/write/close/lseek/fstat） | 高 |
| 可视化工作台 | 展示反汇编列表、CFG、寄存器面板、内存视图和执行轨迹 | 高 |
| 报告导出层 | 支持 `Text / JSON / DOT / HTML` 等输出格式 | 中 |
| 示例与文档体系 | 提供样例程序、演示脚本、使用手册和架构文档 | 高 |

**首期比赛范围：**

- **指令支持以 `RV64I` 为核心 **：保证 64 位用户态程序的可分析与可执行闭环。
- **扩展目标为 `RV64IMC`**：在时间允许的情况下补充 64 位乘除法与压缩指令执行支持。
- **补齐 RV64 关键指令族**：重点覆盖 `LD/LWU/SD`、`ADDIW/ADDW/SUBW`、`SLLW/SRLW/SRAW`、`SLLIW/SRLIW/SRAIW`、`MULW/DIVW/DIVUW/REMW/REMUW`。
- **实现用户态 syscall + 最小文件系统能力**：优先支持 `read/write/openat/close/lseek/fstat/brk/exit/exit_group/ioctl`，并支持基于宿主文件的最小 I/O 映射。
- **支持 ELF 信息恢复**：包括入口点、节区、符号与函数列表。
- **支持交互式执行能力**：包括单步、继续执行、断点、执行上限和轨迹导出。
- **支持教学与答辩友好的工作台视图**：重点展示寄存器、内存、指令和控制流之间的联动。
- **参考 Godbolt 对照验证**：通过 Compiler Explorer 观察 gcc/clang 生成的 RISC-V 汇编与 syscall 调用约定，校验实现一致性。

**功能边界（不包含）：**

- 不追求完整支持全部 RISC-V 扩展、特权级或完整操作系统启动流程。
- 不实现内核级 VFS，仅支持用户态分析/执行所需的最小 syscall 与文件访问能力。
- 不在比赛期内实现 JIT、动态二进制翻译或高性能仿真器。
- 不替代 GDB、QEMU、Ghidra 或 Binary Ninja 等成熟大型工具。
- 不把项目扩展为与本题无关的通用云平台或大型 IDE。

### 2.2 预期使用方式

**作为命令行工具：**

```bash
# 查看 ELF 基本信息
rvkit info example/hello.elf

# 反汇编并输出函数列表
rvkit disasm example/hello.elf

# 生成控制流图
rvkit cfg example/hello.elf --dot out/main.dot

# 单步执行并导出轨迹
rvkit run example/hello.elf --entry main --max-steps 200 --trace out/trace.json

# 在断点处暂停
rvkit run example/hello.elf --break main+0x10

# 打开 Web 工作台
rvkit workbench example/hello.elf
```

**作为交互式工作台：**

```
RISC-V ELF / RAW / Assembly
            ↓
     Loader & Decoder
            ↓
 Static Analysis + Exec Runtime
      ↓                  ↓
 CFG / CallGraph     Registers / Memory / Trace
            ↓
   Web Workbench / Reports
```

**Web UI 主要界面：**

1. **顶部工具栏**：提供文件加载、函数切换、运行/暂停、单步、重置、断点开关、导出报告等操作入口。
2. **左侧项目导航区**：展示 ELF 节区、函数列表、符号表和基础程序信息，支持按函数名或地址快速定位。
3. **中央反汇编主视图**：展示当前函数或当前执行路径的反汇编结果，高亮当前 PC、断点位置和最近一次状态变化。
4. **中央 CFG 图视图**：以基本块为单位展示控制流图，支持节点点击、路径高亮和与反汇编列表联动。
5. **右侧状态面板**：展示通用寄存器、程序计数器、关键 CSR（首版可选）、调用栈摘要和最近一次内存写入。
6. **底部轨迹与输出区**：展示执行日志、Trace Event、错误信息、终止原因和结构化输出摘要。

**核心交互方式：**

- 点击函数列表时，同步刷新反汇编视图、CFG 视图和函数摘要。
- 点击某条指令或某个基本块时，高亮对应控制流节点与前后执行轨迹。
- 执行单步时，自动标记本步修改过的寄存器和内存区域，方便教学和答辩展示。
- 在反汇编列表或 CFG 节点上直接设置断点，暂停后保留现场状态供继续分析。
- 支持把当前分析结果导出为可分享的 HTML 报告或 JSON 快照，便于课程实验和结果复现。

## （3）技术路线说明

### 3.1 整体系统架构

```
┌──────────────────────────────────────────────────────────────┐
│                    CLI / Web Workbench / SDK                │
├──────────────────────────────────────────────────────────────┤
│ Disasm View │ CFG View │ Registers │ Memory │ Trace Panel   │
└──────────────────────────────┬───────────────────────────────┘
                               │
                               ▼
┌──────────────────────────────────────────────────────────────┐
│             Analysis Runtime & Execution Engine             │
├──────────────────────────────────────────────────────────────┤
│ CFG │ CallGraph │ Def-Use │ Breakpoints │ Runner │ Reports  │
└──────────────────────────────┬───────────────────────────────┘
                               │
                               ▼
┌──────────────────────────────────────────────────────────────┐
│                    Typed RISC-V Core Model                  │
├──────────────────────────────────────────────────────────────┤
│ ElfImage │ Function │ Block │ Instruction │ ExecState       │
│ RegisterFile │ Memory │ TraceEvent │ Finding │ Evidence      │
└──────────────────────────────┬───────────────────────────────┘
                               │
                               ▼
┌──────────────────────────────────────────────────────────────┐
│                     Input Adapters / Loader                 │
├──────────────────────────────────────────────────────────────┤
│ ELF Parser │ RAW Loader │ Assembly Import │ Symbol Resolver │
└──────────────────────────────────────────────────────────────┘
```

该架构将“输入装载”“类型化表示”“静态分析”“动态执行”“可视化展示”分层组织，使项目既具备可落地性，也具备后续持续扩展空间。

其中，Web 工作台将采用“**顶部工具栏 + 左侧导航树 + 中央双视图 + 右侧状态面板 + 底部轨迹区**”的布局：

- **顶部工具栏**负责装载样例、运行控制、模式切换和结果导出。
- **左侧导航树**负责展示函数、节区、符号和分析结果索引。
- **中央双视图**以“反汇编列表 + CFG 图”联动为核心，支持从结构视图跳转到指令视图。
- **右侧状态面板**负责展示寄存器、内存摘要、断点列表和最近一次写入记录。
- **底部轨迹区**负责展示事件日志、错误信息和执行摘要，便于复盘。

在实现方式上，计划优先复用 MoonBit 编写的分析与执行内核，通过 `WebAssembly` 输出到浏览器端；Web UI 负责状态编排、图形展示和交互控制，从而避免在前后端分别维护两套核心逻辑。这样既能保证 CLI 与 Web 的行为一致性，也能降低比赛期内的开发复杂度。

### 3.2 高质量类型设计

本项目把高质量类型设计作为核心方法，而不是把 ELF、指令、状态和分析结果都放在弱约束的字符串或动态对象中。计划构建如下类型层次：

- **架构层类型**：`XLen`、`ArchProfile`、`ExtensionSet`
- **装载层类型**：`ElfImage`、`SectionId`、`Symbol`、`FunctionEntry`
- **指令层类型**：`Instruction`、`Operand`、`DecodedInst`、`InstFormat`
- **分析层类型**：`BasicBlock`、`ControlEdge`、`CallEdge`、`UseDefFact`
- **执行层类型**：`ExecState`、`RegisterFile`、`MemoryRegion`、`Breakpoint`、`TraceEvent`
- **结果层类型**：`Finding`、`Severity`、`Evidence`、`ReportSection`

这样设计的价值在于：

1. **让复杂状态可验证**：执行前后状态变化、寄存器更新和控制流跳转都能在类型层面表达清楚。
2. **提升系统可维护性**：分析模块、执行模块和展示模块围绕稳定数据接口协作，降低后续重构成本。
3. **支撑多前端与多视图扩展**：未来新增汇编输入、更多扩展指令或更多报告形式时，不需要推翻现有核心模型。

### 3.3 核心算法与分析能力

首批计划落地的核心能力包括：

1. **ELF 装载与符号恢复**：识别入口地址、节区布局、函数符号与代码区间。
2. **RISC-V 解码与反汇编**：将机器码转换为结构化指令对象与可读文本表示。
3. **控制流与调用关系分析**：恢复基本块边界、分支关系和函数调用边。
4. **基础数据流分析**：构建 def-use 关系，为状态解释和可视化联动提供依据。
5. **可解释执行引擎**：支持单步、继续执行、断点暂停、执行轨迹记录和状态快照。
6. **系统调用与文件访问语义**：实现 `RV64` 用户态常用 syscall 分发与最小文件 I/O 语义，保证常见样例可运行。
7. **报告与可视化导出**：把分析和执行结果输出为文本、JSON、DOT、HTML 与工作台交互视图。

### 3.4 扩展机制与平台化设计

项目不会把所有流程硬编码为一次性脚本，而是围绕以下扩展点组织：

- **ISA 扩展接口**：便于后续增加 `RV64` 相关扩展（`M/C/A/F/D`）与新指令支持。
- **分析 Pass 接口**：允许新增数据流分析、规则检查与差异分析模块。
- **执行事件接口**：允许对执行过程挂接日志、断点、统计与可视化订阅器。
- **Syscall ABI 适配接口**：允许按平台切换 syscall 编号映射与参数约定。
- **文件后端接口**：允许在“内存文件/宿主文件”之间切换，便于教学演示与回归测试。
- **报告接口**：允许把同一份结果渲染成终端文本、结构化 JSON、DOT 图和 Web 视图。
- **样例模板系统**：为教学、答辩和回归测试维护统一示例集。

### 3.5 大模型与智能体工具的作用

| 应用场景 | 具体方式 |
|----------|----------|
| 执行结果解释 | 将寄存器变化、控制流跳转和异常状态组织为自然语言说明 |
| 报告整理 | 自动生成某个样例程序的分析摘要与演示说明 |
| 回归辅助 | 对比两个版本的反汇编、CFG 或轨迹差异并给出摘要 |
| 教学支持 | 把底层执行过程转化为更适合课堂或答辩展示的文字讲解 |

这里大模型和智能体不是替代分析与执行本身，而是建立在平台输出的结构化、高质量数据之上。

## （4）风险分析与应对方案

### 4.1 技术风险

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| 指令集支持范围过大 | 中 | 高 | 首期锁定 `RV64I` 主干，`RV64IMC` 分阶段补齐 |
| syscall/文件语义与真实工具链不一致 | 中 | 高 | 以 Linux RISC-V ABI 为准，并通过 Godbolt + 样例程序对照校验 |
| 执行引擎正确性不足 | 中 | 高 | 通过样例程序、快照测试和静态/动态结果交叉验证逐步收敛 |
| Web 工作台占用过多时间 | 中 | 中 | 先完成 CLI、报告与核心联动，再补充图形化界面 |
| 样例程序复杂度失控 | 中 | 中 | 优先围绕小而完整的教学/验证样例打磨闭环 |

### 4.2 应对方案

- **先闭环、后扩展**：优先完成“装载 - 解码 - 分析 - 执行 - 展示”主链路。
- **先 CLI、后工作台**：先保证工具可运行、可复现，再完善交互体验。
- **先基础 ISA、后扩展 ISA**：优先保证 `RV64I` 的稳定性，再补充 `M/C` 等扩展。
- **先 syscall 主干、后文件能力增强**：先支持 `exit/read/write/openat/close`，再补充 `lseek/fstat/brk/ioctl` 与错误码细节。
- **先标准样例、后复杂案例**：围绕少量代表性程序迭代，避免功能堆砌和范围失控。

## （5）相关研究与实践基础

### 5.1 相关项目与参考方向

1. **RISC-V ISA / ELF / DWARF 相关规范与工具链**：为指令语义、文件格式和调试信息解析提供基础依据。
2. **Spike / QEMU 等执行模型参考**：为解释执行、状态更新和测试样例设计提供参照。
3. **Ghidra / Binary Ninja / objdump 等二进制分析工具**：为反汇编展示、控制流恢复和工作台体验提供启发。
4. **Godbolt（Compiler Explorer）对照分析**：用于验证 gcc/clang 在 `RV64` 下生成的函数序言、调用约定和 syscall 汇编模式。
5. **MoonBit 2026 SCC 鼓励的系统级软件方向**：项目具备明确工程目标、技术可行性和长期演进潜力，符合赛事强调的工程质量导向。

### 5.2 技术现状理解

**RISC-V 指令集特点：**
- 支持 `RV32/RV64` 双位宽语义，定长 32 位基础指令 + 压缩 16 位指令（RVC）
- 模块化扩展设计（I/M/A/F/D/C 等）
- 简洁规整的编码格式，利于解码

**用户态运行特性：**
- Linux RISC-V syscall 采用寄存器传参（`a0-a5`）与 `a7` 传 syscall 编号
- 常见 C 程序依赖基础文件 I/O 与进程退出相关 syscall
- 可通过 Godbolt 快速验证不同编译选项下生成代码的调用模式

**现有工具局限性：**
- 商业工具（IDA/Ghidra）RISC-V 支持有限
- 开源工具功能分散，缺乏统一框架
- 多数实现使用 C/C++，存在安全问题
