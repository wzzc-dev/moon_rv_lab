# 2026 SCC 项目申报书

## 项目名称：RISC-V 二进制分析器/反汇编框架 (RISC-V Binary Analyzer & Disassembly Framework)

---

## （1）项目目标与应用场景

### 1.1 项目目标

本项目旨在构建一个基于 MoonBit 语言开发的 RISC-V 二进制分析器与反汇编框架，提供高性能、可扩展的二进制代码分析能力。该框架将支持：

- **完整的 RISC-V 指令集解析**：覆盖 RV32I/RV64I 基础指令集及常用扩展（M/A/F/D/C 等）
- **精确的反汇编引擎**：将二进制机器码转换为可读的汇编指令
- **控制流分析**：构建函数控制流图（CFG）、识别基本块与调用关系
- **符号还原与重定位分析**：解析 ELF 格式符号表、重定位信息
- **可扩展的插件架构**：支持自定义分析 passes 和输出格式

### 1.2 应用场景

1. **嵌入式系统安全分析**：对 RISC-V 固件进行静态分析，发现潜在安全漏洞
2. **逆向工程与漏洞研究**：辅助安全研究人员分析闭源 RISC-V 二进制程序
3. **编译器验证与优化分析**：验证编译器输出、分析代码优化效果
4. **教学与学术研究**：作为计算机体系结构、系统安全课程的教学工具
5. **IoT 设备固件审计**：针对 RISC-V 架构的物联网设备进行安全审计

### 1.3 解决的问题

- **现有工具链缺口**：主流反汇编工具（如 IDA Pro、Ghidra）对 RISC-V 支持有限或需付费
- **开源工具不成熟**：现有开源 RISC-V 工具功能单一、缺乏系统性框架
- **性能与可扩展性**：Python 等动态语言实现的工具在处理大规模二进制时性能不足
- **类型安全缺失**：C/C++ 实现的工具存在内存安全问题

## （2）交付物说明

### 2.1 核心功能与功能边界（Scope）

**核心功能（必须实现）：**

| 模块 | 功能描述 |
|------|----------|
| ELF 解析器 | 支持 32/64 位 ELF 格式解析，提取段、符号、重定位信息 |
| 指令解码器 | 支持 RV32I/RV64I 及 M/A/F/D/C 扩展的完整解码 |
| 反汇编引擎 | 将机器码转换为 AT&T/Intel 风格汇编文本 |
| 控制流分析 | 函数识别、基本块划分、控制流图构建 |
| CLI 工具 | 命令行界面，支持常用分析操作 |

**扩展功能（优先实现）：**

| 模块 | 功能描述 |
|------|----------|
| 数据流分析 | 常量传播、寄存器追踪 |
| 符号执行基础 | 基础路径约束求解接口 |
| 输出格式扩展 | JSON、XML、Capstone 兼容格式 |
| Python 绑定 | 提供 Python API 便于脚本化分析 |

**功能边界：**

- **支持架构**：RISC-V RV32/RV64（暂不支持其他架构）
- **输入格式**：ELF 可执行文件、原始二进制
- **不支持**：动态二进制分析（DBI）、运行时插桩、完整符号执行引擎

### 2.2 预期使用方式与交互流程

**命令行使用示例：**

```bash
# 基础反汇编
rv-disasm -f firmware.elf -o output.asm

# 生成控制流图（DOT 格式）
rv-disasm -f firmware.elf --cfg -o cfg.dot

# JSON 格式输出
rv-disasm -f firmware.elf --format json -o analysis.json

# 分析特定函数
rv-disasm -f firmware.elf --function main -o main.asm

# 交互式分析（REPL 模式）
rv-disasm -f firmware.elf --interactive
```

**程序化 API 使用：**

```moonbit
// 加载并解析二进制
let binary = Binary::load("firmware.elf")

// 获取所有函数
let functions = binary.get_functions()

// 反汇编特定地址
let instructions = Disassembler::disassemble_range(binary, 0x1000, 0x2000)

// 构建控制流图
let cfg = ControlFlowGraph::build(functions[0])
```

## （4）风险分析与应对方案

### 4.1 技术风险

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| RISC-V 指令集复杂性 | 中 | 高 | 分阶段实现：先基础指令集，后扩展；参考官方规范文档 |
| ELF 格式边界情况 | 中 | 中 | 使用 fuzzing 测试；参考 readelf/objdump 实现 |
| 性能不达预期 | 低 | 中 | 早期进行性能基准测试；预留优化空间 |
| MoonBit 生态限制 | 中 | 中 | 及时与社区沟通；准备替代方案（如 FFI） |

### 4.2 工程风险

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| 开发进度延迟 | 中 | 高 | 采用敏捷开发；优先实现核心功能 |
| 测试覆盖不足 | 低 | 高 | 强制要求单元测试；使用 CI 自动化 |
| 文档滞后 | 中 | 中 | 文档与代码同步编写；使用文档生成工具 |

### 4.3 替代方案

- **性能问题**：如纯 MoonBit 实现性能不足，考虑关键路径使用 Rust FFI
- **复杂分析**：如符号执行过于复杂，改为提供基础框架接口
- **格式支持**：如 ELF 解析过于复杂，优先支持原始二进制 + 简化 ELF

   - LLVM 反汇编实现，输出格式参考

### 5.2 技术现状理解

**RISC-V 指令集特点：**
- 定长 32 位基础指令 + 压缩 16 位指令（RVC）
- 模块化扩展设计（I/M/A/F/D/C 等）
- 简洁规整的编码格式，利于解码

**现有工具局限性：**
- 商业工具（IDA/Ghidra）RISC-V 支持有限
- 开源工具功能分散，缺乏统一框架
- 多数实现使用 C/C++，存在安全问题

### 5.3 本项目创新点

- **类型安全**：使用 MoonBit 的强类型系统避免内存错误
- **模块化设计**：清晰的模块边界，便于扩展
- **性能与安全的平衡**：原生性能 + 内存安全保证

```
原始字节流 → 指令长度判断(16/32位) → 操作码提取 →

```

基本块划分 → 边连接 → CFG 构建
